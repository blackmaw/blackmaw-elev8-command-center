# Architecture Principles

## Independent Product Boundaries

Product source code remains in its canonical product repository.

## Registry-Driven Headquarters

Products, repositories, initiatives, and organizational systems are represented through structured registries.

## Documentation as Infrastructure

Markdown documentation is treated as version-controlled institutional infrastructure.

## Progressive Integration

Static local data is established first. Live GitHub, automation, analytics, finance, and AI integrations are introduced through explicit interfaces.

## Deny-by-Default Security

Sensitive capabilities must require explicit authorization. Client-side visibility is never treated as an authorization boundary.

## Evidence-Based Status

Dashboard status must distinguish:

- Declared
- Planned
- In progress
- Implemented
- Validated
- Accepted
- Blocked

## Auditability

Material changes to registries, governance, permissions, architecture, and release status must be traceable through Git history and decision records.
